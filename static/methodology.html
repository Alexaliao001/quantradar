Methodology

Educational radar — not investment advice. We publish how the score is built so you can distrust us productively.

One public score

The only number we call Score on the product surface is the charts engine mechanical posture score (primary_score / score.final, 0–100). Sub-indicators may exist in the engine payload for research, but the UI must not show multiple “Composite” scores that disagree.

What the score is (and is not)

  • Is: a deterministic technical posture of the current setup given OHLCV + environment inputs.
  • Is not: a forecast that the stock will rise tomorrow, or a guarantee of edge.
  • Same inputs → same score (regression-tested in the engine).

Gates & primary action

Market / sector context and a state code (e.g. pullback vs breakdown) feed a single primary action: Full / Build / Probe / Wait / No / Put-bias. Summary text must match that primary — no “buy” next to “Wait & Watch”.

Data quality

If volume fields are zero or missing, we withhold volume narratives. If options data is simulated or unavailable, options are marked non-actionable. Unknown tickers fail closed — no fabricated buy score.

Pattern “success rates”

Pattern labels and historical efficiency ranks, when shown, must cite the data series and period. We do not invent social proof (user counts) or fake testimonials. Calibrated edges from our private research desk will be published here as they clear verification — not before.

Demo vs live

Demo chips (e.g. INTC) load pre-built artifacts and do not charge credits or hit live market APIs. Live mode requires sign-in and uses the charts fetch path when configured.
